# Parent router shadow operation

This is an opt-in GPT/Codex entry point. `route_work` returns one authoritative Claude answer and may queue one undelivered Qwen candidate after that answer is available. It does not intercept ordinary conversations, change `delegate_claude`, or route a verified Qwen answer to the parent. The dashboard's parent-router section counts only work submitted through this entry point. Production routing cards exclude shadow calls.

A repeat of the same task/work-item/prompt/contract/reference returns the stored paid answer. If a process stopped after the parent decision or paid queue entry, the repeat resumes the same deterministic paid call; if it stopped after the paid answer but before shadow enqueue, it may enqueue the eligible shadow call. A changed policy before paid admission is rejected for manual review rather than silently submitting under a new policy.

## Register a natural case at arrival

Capture the original task, broken single-file Python module and trusted tests before a solution exists. Store the input JSON under ignored `var/router/incoming/` with `origin_kind="natural"`, a stable `origin_ref`, `task_id`, `task_text`, timezone-aware `task_arrived_at` and `captured_at`, `baseline_source`, `tests`, and `output_contract="complete_python_module_v1"`. A test vector is `{"function":"square","args":[2],"expected":4}`. The parser rejects a capture timestamp before arrival or at/after a declared solution availability time. The registrar runs the broken baseline through the digest-pinned Docker verifier and requires a trusted-test failure.

Run `.\.venv\Scripts\python.exe scripts\register-router-case.py --case var\router\incoming\<case>.json` after reviewed shadow activation. Its receipt contains a content-addressed `verifier_ref`. The frozen case includes the baseline failure reason, source/test digests and full verifier-settings digest. A changed verifier setting makes that case ineligible until it is registered and baseline-verified again. Pass the reference with the matching task packet and original prompt to parent `route_work`; use a call budget of at least two and enough reserved tokens for paid plus shadow calls. If the case is unavailable, the router records `verifier_missing` and uses the paid model directly. A snapshot captured after the answer exists must not be entered into the natural cohort.

Keep every attempted, rejected, timed-out and interrupted case in the cohort. The dashboard's model, prompt-version and verifier-reference filters show attempt counts, queue and evaluation coverage, reason groups and provider-specific usage coverage. Prompt and response bytes load only from the operator-authenticated content endpoint when a work item is selected. A passing Qwen candidate is evidence of trusted-test success; it is not evidence of a saved paid bill. The report leaves conditional avoided calls and billed savings unknown until comparable paid work and billing evidence exist.

## Shutdown, rollback and uncertain work

Stop admitting parent-router work before stopping the shadow worker. A queued shadow job remains queued until its deadline; a launched or uncertain job is never automatically resubmitted. Raw output, parsed candidate, independent evaluation and slot release commit in one database transaction. If evaluation persistence fails, the job stays uncertain with its slot held and requires reconciliation; it must not trigger another Qwen send. Restarting the worker registers a new incarnation and can process unrelated work within remaining capacity. For a held uncertain call, use the existing `scripts/reconcile-execution.py` with a correlated agent termination or status receipt; a silent host, stale heartbeat or local process restart is insufficient evidence to release capacity. Never force-clear a held slot to improve throughput.

To roll back shadow admission, activate a separately reviewed policy with `router.mode="disabled"`. This affects later admissions. Inspect already queued and uncertain shadow calls; withdrawn verifier references are rechecked at dispatch and cancel safely before a model send. The paid answer already returned for a shadow task remains authoritative. Keep both policy hashes, approval references and retained audit records for analysis.

At 30 reconciled natural attempts, review independent pass/fail/unknown outcomes, comparison validity, latency, model usage and provider billing coverage. Any live Qwen delivery, new failure gate or automatic gate update requires a separate design and policy review.
