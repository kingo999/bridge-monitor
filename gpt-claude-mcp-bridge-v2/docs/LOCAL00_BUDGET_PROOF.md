# LOCAL-00 conservative prompt budget

The supported baseline is the handoff's model/digest on Ollama 0.30.9. The installed template, default system text, tokenizer metadata and server version were inspected through read-only APIs on 2026-10-15. Reviewed values live in `bridge/local_worker/_baseline.py`; the small fixture is independently fingerprinted with the source. The raw observation and source hashes are under `docs/evidence/local00/`.

For this exact template, the generate request produces one default-system message and one user message. Its template renders the system prefix, supplied user text and assistant prefix. No tools, images, suffix, prior messages or system override are supplied. The dedicated renderer admits only the observed metadata. See version-pinned [generate routing](https://github.com/ollama/ollama/blob/0f047feef52c0c0d62c715cce94d7cac7c2a854b/server/routes.go), [prompt rendering](https://github.com/ollama/ollama/blob/0f047feef52c0c0d62c715cce94d7cac7c2a854b/server/prompt.go) and [template execution](https://github.com/ollama/ollama/blob/0f047feef52c0c0d62c715cce94d7cac7c2a854b/template/template.go).

The observed tokenizer is GPT-2 byte BPE with Qwen2 pretokenization and no added BOS. The reviewed [BPE implementation](https://github.com/ollama/ollama/blob/0f047feef52c0c0d62c715cce94d7cac7c2a854b/tokenizer/bytepairencoding.go) maps each original UTF-8 byte to one initial symbol; splitting partitions the text and pair merges reduce symbol count. Recognized special strings emit one token. The alternate [byte tokenizer path](https://github.com/ollama/ollama/blob/0f047feef52c0c0d62c715cce94d7cac7c2a854b/x/tokenizer/tokenizer_encode.go) likewise uses byte symbols. Thus counting all rendered UTF-8 bytes, including full special-token spellings, is an upper bound. Two further slots conservatively cover BOS/EOS additions.

`upper_bound = UTF8_bytes(system_prefix + focused_prompt + assistant_suffix) + 2`. Permit at most 14336, retaining 2048 output tokens in 16384. This is a conservative upper bound, not an exact tokenizer count. Tests pin 14336/14337, Unicode, retries and changed identities. Recheck current metadata/version before inference, compare actual prompt count afterwards, and block further generation on a contradiction. Unknown metadata/runtime requires a reviewed proof update; no heuristic fallback or download occurs.
