## Objective and authority

Provide one PowerShell command after Windows login/reboot to start or reuse the
dashboard, start or reuse the existing Codex desktop app, and check the existing
registered MCP bridge transports without executing model work. The human request
authorizes this bounded wrapper around the existing launch flow. It does not
authorize changing bridges, registrations, accepted ADRs, credentials, Git state,
Windows startup registration, or stopping/restarting pre-existing processes.

Suggested execution model: Claude Sonnet. The work follows existing stdio MCP and
localhost HTTP patterns with focused lifecycle verification. Advisory only;
the user's configured model remains unchanged.

## Design

- One user entry point: C:/AI/gpt-claude-mcp-bridge-v2/tools/agent-startup/start-agent-stack.ps1. Python helper,
  focused tests, local .gitignore and README may live only in that new directory.
- Derive the checkout from the script directory; use existing Python 3.13 runtime
  and read the existing project .codex/config.toml without writing it.
- Persistent stdio bridges belong to their configured MCP clients. Never leave
  detached stdio servers claiming they are connected to Codex. Start Codex only
  when absent, using installed OpenAI.Codex package/manifest app identity (observed
  PackageFamilyName OpenAI.Codex_2p2nqsd0c76g0, Application Id App), or an explicit
  executable override. Match the installed app, not every ChatGPT-named process.
- Existing Codex and bridge processes must be reused, never restarted. Open the
  trusted checkout in Codex; if the launcher cannot select it automatically, report
  that action clearly. Native app connection readiness is unknown unless observed;
  direct MCP probe health must never be described as native tool reconnection.
- Start or reuse OBS-01 on loopback port 8089. Reuse requires bounded HTTP checks
  that identify this dashboard (HTML/assets and valid snapshot shape), not just
  any HTTP 200. Refuse occupied/unhealthy ports; never kill their owner. A started
  dashboard stays available after the startup script exits, with hidden window.
- Provide HealthOnly (no app/dashboard launch) and SkipAppLaunch controls and an
  optional dashboard port for safe isolated verification. Defaults remain useful
  as one startup command. No installs, login prompts or execution-policy changes.
- Probe all existing named registrations (gpt-architect, gpt-architect-v1,
  gpt-architect-v2, claude-implementer) with fresh temporary MCP stdio clients,
  initialized from the checkout and using their configured command/args/env.
  Deduplicate equivalent launches while reporting every alias. Discover expected
  GPT tools (consult_architect, review_implementation) and the five Claude tools.
  Never invoke GPT consultations/reviews or Claude implement_changes from health
  checks. Read-only Claude source-state/receipt checks may inspect current state;
  receipt recovery follows existing FLOW-01 semantics and must not relaunch work.
- Bound waits, HTTP sizes, subprocess output and command timeouts. Capture only
  safe diagnostic codes/metadata; no prompts, source, CLI auth output, credentials,
  environment values or raw exceptions in the report/logs. Preserve process errors
  as failures rather than claiming readiness. Separate transport health, CLI auth
  availability, native app connection unknown, and incomplete dashboard telemetry.
- Emit a concise human report plus JSON summary with meaningful nonzero exit on
  failed checks. Keep own logs/state under ignored C:/AI/gpt-claude-mcp-bridge-v2/tools/agent-startup/.runtime.
  Do not persist secrets or fabricate cold-reboot evidence.

## Acceptance and verification

- Test missing dependencies/configuration, timeout cleanup, expected tool checks,
  equivalent aliases, occupied/unhealthy dashboard port, cold dashboard start,
  repeated-run reuse and health-only no launches. Use fixtures, no model work or
  new dependencies. Test runtime behavior rather than mirrored implementation.
- First write focused failing tests, then implementation, then run those tests.
- Independent reviewer examines actual new source and runs relevant tests.
- Run real model-free MCP probes and real PowerShell entry point against the
  existing app/dashboard, verify repeated invocation preserves their process IDs.
- Separately exercise dashboard startup/reuse on an unused loopback port, and clean
  up only the test-created dashboard by verified process identity. Do not reboot
  Windows or restart Codex/GPT as part of verification; report this limitation.
- Compare GPT v1/v2 sources, all registrations, accepted ADRs, operating agreement,
  prior CTX/OBS/FLOW deliverables, Git HEAD/index and pre-existing process identities
  to the saved baseline. Do not stage, commit, push or install startup tasks.
